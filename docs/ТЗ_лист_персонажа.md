# ТЗ: Интерактивный лист персонажа D&D для GitHub Pages

## 1. Цель проекта

Статический одностраничный сайт (SPA) для ведения нескольких листов персонажей D&D 5e (с поддержкой хоумбрю-механик). Без бэкенда и базы данных — вся логика и хранение на клиенте. Хостинг — GitHub Pages (статическая раздача из `dist/`).

Ключевая идея: **любое числовое значение на листе = база + модификатор характеристики (опц.) + бонус мастерства (опц.) + список произвольных бонусов**, которые можно добавлять и удалять через UI, не трогая код.

## 2. Технологический стек

- **React 18 + Vite** (build step перед деплоем)
- **TypeScript** — обязательно, учитывая связанность полей друг с другом (см. модель данных ниже) — типы существенно снижают риск ошибок пересчёта
- Стейт-менеджмент: React Context + `useReducer`, либо Zustand (на усмотрение исполнителя, но состояние должно быть единым деревом, синхронизируемым с localStorage)
- Библиотека сжатия для шеринг-ссылок: `lz-string`
- Без CSS-фреймворков обязательности — можно чистый CSS/CSS Modules, или Tailwind (на усмотрение исполнителя)
- Иконки: `lucide-react` (лёгкая, часто уже используется в подобных проектах)

## 3. Деплой на GitHub Pages

- `vite.config.ts`: указать `base: '/<имя-репозитория>/'`
- Добавить GitHub Actions workflow (`.github/workflows/deploy.yml`), который на пуш в `main` собирает проект (`npm run build`) и публикует `dist/` в ветку `gh-pages` (например, через `peaceiris/actions-gh-pages` или встроенный `actions/deploy-pages`)
- Приложить в репозиторий короткую инструкцию (`README.md`) — как включить GitHub Pages в настройках репозитория (Source: GitHub Actions / gh-pages branch)

## 4. Модель данных

### 4.1 Общие типы

```typescript
type AbilityKey = 'STR' | 'DEX' | 'CON' | 'INT' | 'WIS' | 'CHA';

type BonusType = 'fixed' | 'dice' | 'ability_mod';

interface Bonus {
  id: string;
  label: string;            // источник, напр. "Зачарованная секира +1"
  type: BonusType;
  value?: number;           // для 'fixed' — целое число (может быть отрицательным)
  dice?: string;            // для 'dice' — нотация "1к4", "2к6" и т.п.
  abilityKey?: AbilityKey;  // для 'ability_mod' — какую характеристику подставлять
  appliesTo: string;        // id StatField/ResourceTracker/Attack-подполя, к которому привязан
}
```

### 4.2 Универсальное числовое поле (StatField)

Это ядро системы. К нему привязывается кнопка "+", модальное окно бонуса и итоговый расчёт.

```typescript
interface StatField {
  id: string;
  label: string;               // "Атлетика", "КД", "Инициатива" и т.п.
  baseValue: number;            // редактируется вручную
  linkedAbility?: AbilityKey;   // если задано — автоматически прибавляется текущий модификатор этой характеристики
  proficient?: boolean;         // если true — автоматически прибавляется текущий бонус мастерства
  bonusIds: string[];           // ссылки на Bonus.id (из character.bonuses), приложенные к этому полю
}
```

**Расчёт итогового значения поля** (см. также раздел 5):

```
flatTotal =
    baseValue
  + (linkedAbility ? abilityModifier(linkedAbility) : 0)
  + (proficient ? proficiencyBonus(level) : 0)
  + sum(bonus.value for bonus in attachedBonuses where type === 'fixed')
  + sum(abilityModifier(bonus.abilityKey) for bonus in attachedBonuses where type === 'ability_mod')

diceFormula = join(' + ', [bonus.dice for bonus in attachedBonuses where type === 'dice'])

display = diceFormula ? `${flatTotal} + ${diceFormula}` : `${flatTotal}`
```

Пример отображения: `13 + 1к4` (если к полю приложен кубиковый бонус) или просто `13` (если кубиковых бонусов нет).

### 4.3 Персонаж (Character)

```typescript
interface Character {
  id: string;
  name: string;
  meta: {
    race: string;
    className: string;       // свободный текст, напр. "Варвар (Путь Фанатика)"
    level: number;            // управляет бонусом мастерства
    alignment: string;
    faction: string;         // свободный текст, напр. "Орден Перчатки"
    background: string;
  };
  themeColor: string;         // hex, акцентный цвет карточки

  abilities: Record<AbilityKey, StatField>;   // 6 характеристик (без linkedAbility/proficient)

  combat: {
    hpMax: StatField;
    hpCurrent: number;       // просто число с +/- контролами, не через бонусы
    hpTemp: number;
    ac: StatField;
    speed: StatField;
    initiative: StatField;   // обычно linkedAbility: 'DEX'
  };

  savingThrows: Record<AbilityKey, StatField>; // 6 полей, linkedAbility = сама характеристика, proficient — переключатель

  skills: SkillField[];      // см. 4.4

  attacks: Attack[];         // см. 4.5

  spellcasting?: SpellcastingBlock;  // см. 4.6, блок можно включить/выключить

  resources: ResourceTracker[]; // см. 4.7 — ярость, всплеск действия, ячейки заклинаний и т.д.

  features: { id: string; title: string; description: string }[]; // способности/черты
  equipment: { id: string; name: string; note: string }[];
  proficienciesAndLanguages: string; // свободный текст (владения, языки)
  notes: string;              // свободное поле заметок

  bonuses: Bonus[];            // ПЛОСКИЙ список всех бонусов персонажа (см. appliesTo в Bonus)
}
```

### 4.4 Навык (SkillField)

```typescript
interface SkillField extends StatField {
  linkedAbility: AbilityKey;   // обязателен для навыка
  custom?: boolean;            // true — пользовательский навык, можно переименовать/удалить
}
```

Стандартный набор из 18 навыков 5e создаётся при создании персонажа с преднастроенными `linkedAbility` (Атлетика→STR, Акробатика→DEX, и т.д. — стандартная таблица 5e). Пользователь может добавить свои дополнительные (`custom: true`) и удалить их (стандартные — только менять `proficient`/бонусы, не удалять).

### 4.5 Атака/оружие (Attack)

```typescript
interface Attack {
  id: string;
  name: string;              // "Секира"
  attackBonus: StatField;    // обычно linkedAbility: STR/DEX, proficient: true
  damageDice: string;        // "1к12", редактируется как текст
  damageBonus: StatField;    // обычно linkedAbility на ту же характеристику, + произвольные бонусы (напр. +1к6 огня от зачарования)
  damageType: string;        // "рубящий", свободный текст
  notes?: string;
}
```

Урон отображается аналогично StatField: `flatTotal` из `damageBonus` + `damageDice` + кубиковые бонусы из `damageBonus.bonusIds`, например: `1к12 + 3 + 1к6 (огонь)`.

### 4.6 Заклинания (SpellcastingBlock, опционально)

```typescript
interface SpellcastingBlock {
  enabled: boolean;
  spellSaveDC: StatField;        // baseValue обычно 8, proficient: true, linkedAbility: INT/WIS/CHA
  spellAttackBonus: StatField;   // аналогично, без базовых 8
  cantrips: string[];            // список строк (можно редактировать построчно)
  spellbook: { id: string; name: string; level: number; prepared: boolean }[];
}
```

Ячейки заклинаний (по кругам) реализуются как обычные `ResourceTracker` (см. ниже) — отдельный трекер на каждый круг, это унифицирует их с яростью/всплеском действия и одной и той же логикой сброса.

### 4.7 Трекер ресурсов (ResourceTracker)

Универсальный тип для всего, что тратится и восстанавливается отдыхом: ярость, всплеск действия, второе дыхание, ячейки заклинаний по кругам, магическое восстановление и т.п.

```typescript
interface ResourceTracker {
  id: string;
  label: string;             // "Ярость", "Ячейки 1 круга"
  max: number;                // редактируется вручную (не через систему бонусов — по решению, см. п. 9)
  used: number;                // сколько потрачено (соответствует числу отмеченных чекбоксов)
  resetOn: 'short_rest' | 'long_rest' | 'both' | 'manual';
}
```

UI: ряд чекбоксов `max` штук, `used` из них отмечены. Клик по чекбоксу переключает потрачено/не потрачено.

## 5. Формулы по умолчанию (стандартные правила D&D 5e)

- **Модификатор характеристики:** `floor((score - 10) / 2)`
- **Бонус мастерства от уровня:**

| Уровень | Бонус |
|---|---|
| 1–4 | +2 |
| 5–8 | +3 |
| 9–12 | +4 |
| 13–16 | +5 |
| 17–20 | +6 |

Всё это — только стартовые значения для вычислений. Пользователь в любой момент может напрямую переписать `baseValue` любого поля, если хочет отойти от стандартных правил (уже есть прецедент — хоумбрю-способности в текущей кампании).

## 6. Функциональность

### 6.1 Управление персонажами

- Список персонажей (сайдбар слева или экран выбора) — имя, короткая подпись (раса/класс), акцентный цвет
- Создать нового (с шаблоном по умолчанию — все поля обнулены/стандартный набор навыков)
- Переименовать, дублировать (удобно для NPC-вариаций), удалить (с подтверждением)
- Переключение между персонажами не должно требовать перезагрузки страницы

**Приёмка:** создание, переименование и удаление персонажа мгновенно отражается в списке и в localStorage.

### 6.2 Структура карточки персонажа

Разделы сверху вниз (каждый — сворачиваемая секция):

1. **Шапка:** имя, раса, класс, уровень, мировоззрение, фракция/предыстория, выбор акцентного цвета
2. **Характеристики:** 6 StatField, каждая со своей кнопкой "+"
3. **Боевые параметры:** HP (макс + текущие/временные с +/- контролами), КД, Скорость, Инициатива — у каждого своя "+"
4. **Спасброски:** 6 StatField с переключателем "владение"
5. **Навыки:** список SkillField с переключателем "владение", + кнопка "добавить свой навык"
6. **Атаки/оружие:** список Attack, кнопка "добавить атаку"
7. **Заклинания** (если включено): DC, бонус атаки заклинанием, заговоры, книга заклинаний
8. **Ресурсы:** список ResourceTracker с чекбоксами + кнопки "Короткий отдых" / "Длинный отдых"
9. **Способности:** свободный список title+description, добавление/удаление/редактирование
10. **Снаряжение:** свободный список
11. **Владения и языки:** свободный текст
12. **Заметки:** свободный текст

**Приёмка:** каждый из разделов рендерится, редактируется и сохраняется независимо от остальных.

### 6.3 Универсальная система бонусов

- Рядом с каждым StatField (и полями внутри Attack) — кнопка `+`
- Клик открывает модальное окно с полями:
  - **Название/источник** (текст, напр. "Кольцо защиты +1")
  - **Тип:** переключатель из трёх вариантов — *Фиксированное значение* / *Кубик* / *Модификатор характеристики*
    - Фиксированное — числовой инпут (разрешены отрицательные)
    - Кубик — текстовый инпут с валидацией по маске `\d+к\d+` (плюс несколько кнопок-пресетов: 1к4, 1к6, 1к8, 1к10, 1к12, 2к6)
    - Модификатор характеристики — выпадающий список из 6 характеристик
- После сохранения бонус добавляется в `character.bonuses`, поле мгновенно пересчитывается
- **Aside-панель справа:** плоский список всех бонусов текущего персонажа — с указанием, к какому полю каждый привязан (человекочитаемое название поля), с кнопкой удаления у каждого

**Приёмка:** добавление/удаление бонуса в модальном окне или aside-панели мгновенно пересчитывает связанное поле; список в aside всегда соответствует фактическому состоянию `character.bonuses`.

### 6.4 Бросок кубика

- Рядом с итоговым значением, если у поля есть кубиковые бонусы, — кнопка **"Бросить"**
- Клик генерирует случайный ролл (через `Math.random()` или `crypto.getRandomValues`) по всем кубиковым компонентам поля, прибавляет `flatTotal`, и показывает результат (всплывающая подсказка/тост), например: `Бросок: 13 + (1к4 → 3) = 16`
- Формула (`13 + 1к4`) всегда отображается рядом со значением независимо от того, нажимали ли на "Бросить" — чтобы можно было бросать кубики физически за столом

**Приёмка:** результат броска отображается, не изменяет постоянное состояние персонажа (это одноразовый показ, не сохраняется).

### 6.5 Сохранение (localStorage)

- Ключи: `dnd-sheets:index` → массив `{id, name}[]`; `dnd-sheets:char:<id>` → полный JSON персонажа
- Автосохранение при любом изменении состояния (дебаунс ~300 мс)
- При загрузке приложения — восстановление списка и данных из localStorage
- Версионирование схемы: поле `schemaVersion` в корне Character (на будущее, для миграций)

**Приёмка:** обновление страницы (F5) не приводит к потере данных.

### 6.6 Шеринг

**А. Копирование в буфер обмена**
- Кнопка "Скопировать JSON" на карточке персонажа — сериализует текущего персонажа в JSON и кладёт в буфер обмена (`navigator.clipboard.writeText`)
- Кнопка "Вставить из буфера" в списке персонажей — читает буфер, парсит JSON, валидирует по схеме, добавляет как нового персонажа (при совпадении имени — предлагает переименовать или перезаписать)

**Б. Ссылка с данными в URL**
- Кнопка "Поделиться ссылкой" — сериализует персонажа, сжимает через `lz-string` (`compressToEncodedURIComponent`), кладёт в `location.hash` (напр. `#char=<сжатые-данные>`), копирует получившуюся ссылку в буфер обмена
- При открытии приложения по ссылке с `#char=...` — распаковать, показать модалку "Импортировать персонажа «Имя»?" с кнопками Импортировать / Отменить (чтобы не перезаписывать существующих персонажей случайным переходом по ссылке)

**Приёмка:** персонаж, экспортированный любым из двух способов, при импорте на другом устройстве/в другом браузере воспроизводится идентично (все поля, бонусы, ресурсы).

### 6.7 Короткий/длинный отдых

- Две кнопки в разделе "Ресурсы"
- "Короткий отдых" — обнуляет `used` у трекеров с `resetOn: 'short_rest'` или `'both'`
- "Длинный отдых" — обнуляет `used` у трекеров с `resetOn: 'long_rest'`, `'short_rest'` или `'both'` (длинный отдых включает эффект короткого)
- Трекеры с `resetOn: 'manual'` не затрагиваются автоматически — сбрасываются только вручную кликом по чекбоксам

## 7. UI/UX и стиль

- Тёмная фэнтезийная тема (аналогично PDF-версии): тёмный фон, акцентный цвет секций — берётся из `character.themeColor`, настраивается через цветовой пикер в шапке карточки
- Заголовки секций — цветные плашки (как в PDF), чтобы визуально разграничивать блоки
- Чёткая типографика, без лишней декоративности — приоритет читаемости за игровым столом

## 8. Адаптивность

- Мобильная вёрстка обязательна — приложение будет открываться с телефона/планшета прямо во время сессии
- Aside-панель бонусов на мобильном — выезжающая панель (drawer), а не постоянная колонка
- Секции карточки — сворачиваемые (аккордеон), чтобы не скроллить бесконечно на маленьком экране

## 9. Вне скоупа v1 / бэклог на будущее

- Автоматический расчёт HP по таблицам хитов классов при левел-апе (сейчас `hpMax.baseValue` — просто редактируемое число, ASI/увеличение HP при левел-апе добавляется вручную как бонус или правка `baseValue`)
- Полная база стандартных заклинаний/монстров/предметов (сейчас все текстовые поля свободные)
- Синхронизация между несколькими устройствами в реальном времени (нет бэкенда — вне скоупа по определению задачи)
- Мультиплеер/просмотр листов другими игроками онлайн одновременно

## 11. Чек-лист приёмки (для самопроверки при разработке)

- [ ] Изменение характеристики мгновенно пересчитывает все зависимые поля (навыки, спасброски, КД, атаки, DC заклинаний)
- [ ] Изменение уровня пересчитывает бонус мастерства и все поля с `proficient: true`
- [ ] Добавление/удаление бонуса через модалку работает для любого StatField на листе
- [ ] Aside-панель бонусов синхронна с реальным состоянием, удаление оттуда тоже работает
- [ ] Кубиковые бонусы отображаются формулой и по кнопке "Бросить" дают случайный результат
- [ ] Данные переживают перезагрузку страницы (localStorage)
- [ ] Копирование JSON в буфер и вставка обратно воссоздают персонажа один в один
- [ ] Ссылка-шеринг открывается на чистом браузере (без localStorage) и предлагает импорт
